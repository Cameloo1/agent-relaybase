# Agent transcript and tool traces

Relaybase presents observable Agent work inline with the conversation in both the `Ctrl+G` Agent pane and the full Agent Chat page. The transcript is derived from the same authenticated, persisted run-event stream used for responses and approvals; it is not a second protocol and it does not expose private model reasoning.

User messages, Agent text, public processing state, tool calls, approvals, diagnostics, and outcomes remain in their chronological positions. A tool call has a stable identifier and updates in place as it moves through active, approval-required, completed, failed, or cancelled states. Completed tool results retain up to five visible terminal rows at the current width; longer output shows an accurate `+N rows` marker. Click the tool block, or select it with Up/Down and press Enter or Space, to expand or collapse its bounded sanitized result. `Ctrl+E` expands or collapses all available tool details while the transcript owns input. Conversation text and tool results wrap at word boundaries in both the docked and full-width views; long unbroken tokens hard-wrap instead of being discarded.

Long threads and expanded tool results use a process-local virtual row index. Relaybase caches bounded wrapping metadata for the most recent terminal widths and materializes only the rows intersecting the current viewport. The complete retained transcript remains available for scrolling, copy, replay, and expansion; the cache is not persisted and does not change daemon events, approvals, or transcript retention.

The daemon formats structured results deterministically, bounds retained content, and applies normal secret redaction before SQLite persistence and SSE publication. Large results explicitly report content that was not retained and direct the operator to export the full result. Historical tool events without the newer presentation projection are backfilled from their persisted observable event fields.

Only the newest foreground active operation shimmers. The animation clock runs only when the authenticated Agent event stream is connected, initial replay is complete, the daemon reports the run as `running`, and a foreground active transcript row exists. Reconnect, replay, approval-waiting, completed, failed, cancelled, offline, and stream-closed states stop the clock immediately, so motion is an authoritative working signal rather than a generic loading decoration. Observable provider response turns appear as `Thinking` before the first tool or response and `Reviewing tool result` after a tool completes; these labels describe public execution state and never contain private model reasoning. Other concurrent work uses a static active marker, and all terminal states are motionless. Frames are process-local and are never persisted or sent over SSE. Set `RELAYBASE_TUI_REDUCED_MOTION=1` to keep active rows static, or `RELAYBASE_TUI_ASCII=1` for ASCII status markers. `TERM=dumb` also selects the ASCII fallback automatically.

`Ctrl+G` opens or closes the one-third-width Agent pane, with a dedicated modal fallback on narrower terminals. `F6` opens the full-width Agent Chat page. `F6` or Esc returns to the exact workspace page, pane selection, focus, Composer draft, and scroll state. The side pane and full page share the active thread and transcript while keeping independent scroll offsets.

Replay and reconnect reduce events idempotently by stable item ID and event sequence. Expansions survive replay, and a terminal run event converts any orphaned active item to completed, failed, or cancelled. Status text is always present, so color and animation are supplementary.

Maintainers can run `npm run agent:live:activity -- --preflight` to validate the configured model and safety caps without network use. `npm run agent:live:activity` performs one bounded, read-only `list_apps` run and verifies the live activity lifecycle, cost boundary, and secret scan.
